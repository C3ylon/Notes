# Python 名称作用域（Scope）

## 1. 作用域与名称查找

Python 中，作用域（Scope）决定了一个名称在哪些代码区域内可以被访问，以及访问该名称时应该从哪里查找对应的绑定。

Python 普通名称查找遵循 LEGB 规则，按照以下顺序依次查找：

| 顺序 | 作用域 | 含义 |
| :--- | :--- | :--- |
| L | Local | 当前局部作用域 |
| E | Enclosing | 外围函数作用域 |
| G | Global | 当前模块的全局作用域 |
| B | Builtins | Python 内置作用域 |

例如：

```python
x = "global"

def outer():
    x = "enclosing"

    def inner():
        x = "local"
        print(x)

    inner()

outer()
# local
```

名称查找从当前作用域开始，依次向外围作用域查找，找到第一个匹配的名称后停止。

需要注意：

- LEGB 主要描述普通函数代码块中的名称查找规则。
- 类定义代码块有特殊的命名空间行为，类命名空间不会自动成为方法的外围作用域。
- 列表、集合、字典推导式和生成器表达式也有自己的特殊作用域规则。

## 2. L：Local（局部作用域）

### 2.1 局部变量

在函数内定义的局部变量名称属于当前函数的局部作用域。

```python
def fn():
    a = 1
    b = {}
    print(locals())

fn()
# {'a': 1, 'b': {}}
```

函数内的 `locals()` 可以获取当前局部作用域的信息。

局部变量名称的作用域是当前函数，不会自动泄漏到外围函数或全局作用域。

```python
def fn():
    a = 1

fn()

print(a)
# NameError
```

### 2.2 局部变量的确定规则

Python 会在编译函数时，根据整个代码块中的名称绑定操作确定名称属于哪个作用域，而不是在运行时根据名称第一次出现时是读还是写来决定。

如果一个名称在当前函数代码块中存在绑定操作，那么除非使用 `global` 或 `nonlocal` 声明，否则该名称会被视为当前函数的局部变量。

常见的名称绑定操作包括：

- 函数参数定义。
- 普通赋值和增强赋值。
- `for` 循环的迭代变量。
- `with ... as` 的目标变量。
- `except ... as` 的异常变量。
- `import` 导入的名称。
- `def` 定义的函数名称。
- `class` 定义的类名称。
- 海象运算符 `:=`。

例如：

```python
a = 1

def fn():
    print(a)
    a = 2

fn()
```

运行时会产生：

```text
UnboundLocalError
```

原因是：

1. Python 编译 `fn()` 时，发现其中存在 `a = 2`。
2. 因此将 `a` 确定为 `fn()` 的局部变量。
3. 执行 `print(a)` 时，尝试读取当前函数的局部变量 `a`。
4. 此时 `a` 尚未绑定值，因此产生 `UnboundLocalError`。

即使赋值语句位于读取语句之后，作用域的判断也不会改变。

`UnboundLocalError` 是 `NameError` 的子类。

### 2.3 `global`

在函数内使用 `global` 声明名称时，可以将该名称绑定到当前模块的全局命名空间，而不再将它视为当前函数的局部变量。

```python
g = 1

def fn():
    global g
    g = 2
    print(locals())

fn()

print(g)
# 2

# locals() 为 {}
```

`global` 声明的名称不会作为当前函数的局部变量出现在 `locals()` 中。

`global` 声明的名称不要求事先在全局作用域中存在，也可以用于创建新的全局名称：

```python
def fn():
    global new_var
    new_var = 123

fn()

print(new_var)
# 123
```

注意：在当前函数代码块中，`global` 声明之前不能出现对该名称的读写操作，否则会产生 `SyntaxError`。

```python
g = 1

def fn():
    # 声明 global g 前的读操作：
    # print(g)
    # SyntaxError: name 'g' is used prior to global declaration

    # 声明 global g 前的写操作：
    # g = 2
    # SyntaxError: name 'g' is assigned to before global declaration

    global g
```

### 2.4 `locals()`

`locals()` 用于获取当前局部命名空间的信息，但不同作用域和 Python 版本之间存在差异。

对于函数、生成器和协程等优化作用域：

- Python 3.13 及以后，每次调用 `locals()` 都会返回一个新的字典快照。
- 字典包含当前已经绑定的局部变量，以及当前函数引用的外围闭包变量。
- 修改返回的字典不会修改实际的局部变量。
- 之后局部变量发生变化，也不会反向影响之前返回的字典。

例如：

```python
def fn():
    a = 1

    d = locals()
    d['a'] = 2

    print(a)
    # 1

    print(d)
    # {'a': 2}

fn()
```

Python 3.12 及以前，函数作用域中 `locals()` 的修改行为存在实现差异，不应依赖修改返回字典来修改实际局部变量。

在模块作用域和类定义代码块中，`locals()` 返回对应的命名空间映射。

## 3. E：Enclosing（外围函数作用域）

### 3.1 嵌套函数

函数内可以嵌套定义其他函数。

在内层函数中访问某个名称时，如果当前函数没有将其确定为局部变量，就会继续向外围函数作用域查找。

```python
def fn():
    a = 1

    def gn():
        print(a)

    gn()

fn()
# 1
```

这里 `gn()` 中的 `a` 来自外围函数 `fn()`。

内层函数对外围函数中的名称进行读取时，该名称称为自由变量（Free Variable）。

如果内层函数引用了外围函数中的变量，Python 可以通过闭包（Closure）保存对外围变量的引用。

### 3.2 `nonlocal`

在内层函数中使用 `nonlocal` 声明名称时，可以使该名称引用最近的外围函数作用域中已经存在的同名变量。

该名称必须存在于某个外围函数作用域中，否则会产生 `SyntaxError`。

```python
def fn():
    a = 1

    def gn():
        nonlocal a
        a = 2

    gn()
    print(a)

fn()
# 2
```

这里 `gn()` 修改的是外围函数 `fn()` 中的变量，而不是创建一个新的局部变量。

`nonlocal` 声明的名称仍然可以出现在 `locals()` 返回的字典中，因为当前函数引用了对应的外围闭包变量。

```python
def fn():
    i = 1
    not_use = 2

    def gn():
        nonlocal i
        print(locals())

    gn()
    # {'i': 1}

    print(gn.__closure__)
    # 包含保存 i 的 Cell 对象

fn()
```

`__closure__` 返回闭包中保存的 Cell 元组，其元素顺序与 `__code__.co_freevars` 中的名称顺序一致。

可以使用以下属性查看闭包变量的名称：

```python
print(gn.__code__.co_freevars)
```

注意：

- `nonlocal` 查找的是外围函数作用域，不包括模块全局作用域。
- `nonlocal` 也不能用于引用类命名空间中的名称。
- 与 `global` 类似，在当前函数内且声明语句之前，不能出现对该名称的读写操作。

### 3.3 修改对象与重新绑定名称的区别

使用 `nonlocal` 的前提是需要重新绑定外围变量的名称。

如果只是修改外围变量所引用的可变对象，则不需要 `nonlocal`。

```python
def fn():
    a = []

    def gn():
        a.append(1)

    gn()
    print(a)

fn()
# [1]
```

这里 `a.append(1)` 修改的是列表对象本身，并没有重新绑定名称 `a`。

而下面的代码需要使用 `nonlocal`：

```python
def fn():
    a = []

    def gn():
        nonlocal a
        a = [1]

    gn()
    print(a)

fn()
# [1]
```

两者的区别在于：

- `a.append(1)`：修改 `a` 引用的对象。
- `a = [1]`：将名称 `a` 重新绑定到另一个对象。

### 3.4 `nonlocal` 的最近外围作用域

当存在多层嵌套函数时，`nonlocal` 会选择最近的、包含该名称绑定的外围函数作用域。

```python
def fn():
    j = 1

    def hn():
        j = 2

        def kn():
            nonlocal j
            j = 3

        kn()
        print(j)

    hn()
    print(j)

fn()
# 3
# 1
```

这里 `kn()` 中的 `nonlocal j` 修改的是 `hn()` 中的 `j`，而不是最外层 `fn()` 中的 `j`。

## 4. G：Global（全局作用域）

全局作用域指当前模块的全局命名空间。

在模块中定义的变量名称会出现在 `globals()` 返回的字典中。

```python
a = 1
b = {}

print(globals())
# {... 'a': 1, 'b': {}}
```

在模块级别，`globals()` 和 `locals()` 返回同一个命名空间。

```python
print(globals() is locals())
# True
```

需要注意：

- 函数中的 `globals()` 指向函数定义所在模块的全局命名空间。
- 全局作用域不是 Python 内置作用域。
- `global` 声明所指向的是模块全局命名空间，而不是内置命名空间。

## 5. B：Builtins（内置作用域）

当名称在 Local、Enclosing 和 Global 中都没有找到时，Python 会继续在内置命名空间中查找。

内置命名空间通常对应 `builtins` 模块。

例如：

```python
print(len([1, 2, 3]))
# 3
```

这里的 `len` 就来自内置命名空间。

内置名称也可以被其他作用域中的同名名称覆盖。

```python
len = 123

print(len)
# 123
```

此时名称查找会优先找到模块全局作用域中的 `len`，而不是内置函数 `len`。

## 6. 类作用域（Class Scope）

类定义代码块具有自己的命名空间。

类定义代码块执行时，其中定义的名称会保存在类的命名空间中，类定义结束后，这些名称成为类的属性。

```python
a = 1

class cl:
    b = 2
    print(locals())
    print(globals())
```

其中：

- `locals()` 可以看到类命名空间中的 `b`。
- `globals()` 可以看到模块全局命名空间中的 `a`。

### 6.1 类属性与实例属性

类属性在执行类定义代码块时创建并绑定到类的命名空间中。

如果实例本身没有对应的实例属性，那么通过实例访问该名称时，可以找到类属性。

```python
class cl:
    l = []

a = cl()
a.l.append('a')

b = cl()

print(b.l)
# ['a']
```

这里 `a.l` 和 `b.l` 都引用类属性 `cl.l` 指向的同一个列表对象。

但如果通过实例重新绑定属性，则会创建实例自己的属性，而不会修改类属性：

```python
class cl:
    l = []

a = cl()
b = cl()

a.l.append(1)

print(b.l)
# [1]

a.l = [2]

print(a.l)
# [2]

print(b.l)
# [1]
```

因此：

- `a.l.append(1)`：修改类属性引用的列表对象。
- `a.l = [2]`：创建实例 `a` 自己的属性 `l`，不影响类属性。

### 6.2 类作用域不会成为方法的外围作用域

类作用域有一个特殊规则：类中定义的名称不会自动成为方法的外围词法作用域。

```python
x = 'global'

class cl:
    x = 'class'

    def fn(self):
        print(x)
        print(self.x)

cl().fn()
```

输出：

```text
global
class
```

方法中的 `x` 不会自动查找类作用域中的 `x`，而是按照 LEGB 规则继续查找全局作用域，最终找到模块级别的 `x`。

如果需要访问类属性，可以通过 `self.x` 或 `cl.x` 等方式访问。

需要区分：如果类定义本身嵌套在外围函数中，类定义代码块仍然可以访问外围函数的变量，但这不代表类命名空间会成为其方法的外围作用域。

## 7. 推导式作用域（Comprehension Scope）

Python 3 中，列表推导式、集合推导式、字典推导式和生成器表达式具有独立的迭代变量作用域。

### 7.1 列表推导式

```python
i = 0

l = [i for i in range(5)]

print(i)
# 0
```

列表推导式中的迭代变量 `i` 不会泄漏到外围作用域。

而普通 `for` 循环不会创建新的作用域：

```python
l = []

for i in range(5):
    l.append(i)

print(i)
# 4
```

因此，普通 `for` 循环结束后，迭代变量仍然可以在外围作用域中访问。

集合推导式和字典推导式具有类似的迭代变量隔离规则。

### 7.2 海象运算符的特殊情况

推导式中的海象运算符 `:=` 有特殊的名称绑定规则。

它绑定的名称属于推导式所在的外围作用域，而不是推导式自己的迭代变量作用域。

```python
l = [(x := i) for i in range(5)]

print(x)
# 4
```

因此，不能简单地认为推导式内部定义的所有名称都不会泄漏。

另外，在类作用域中的推导式内使用海象运算符绑定外围名称会受到限制，会产生 `SyntaxError`。

### 7.3 生成器表达式

生成器表达式同样具有独立的迭代变量作用域。

```python
i = 0

g = (i for i in range(5))

print(i)
# 0

print(list(g))
# [0, 1, 2, 3, 4]
```

需要注意，生成器表达式的最外层可迭代对象表达式会在生成器表达式创建时立即求值，而后续迭代及生成器主体中的表达式是在迭代时执行的。

### 7.4 Python 3.12 起的实现优化

Python 3.12 起，CPython 通过 PEP 709 对列表、集合和字典推导式进行了内联优化。

底层实现不再必然创建独立的隐式函数帧，但推导式迭代变量不泄漏到外围作用域的语言语义没有改变。

## 8. 名称空间与对象生命周期的补充

作用域主要解决名称在哪里可以被访问的问题，而对象生命周期解决对象何时创建以及何时被释放的问题。

两者相关，但不是同一个概念。

### 8.1 函数默认参数

函数默认参数表达式只会在对应的 `def` 语句执行时求值一次，并将计算结果保存在函数对象中。

后续调用函数时，如果没有提供对应参数，就会重复使用该默认值，不会重新计算默认参数表达式。

```python
def fn(l=[]):
    l.append('a')
    print(l)

fn()
# ['a']

fn()
# ['a', 'a']
```

这里两次调用使用的是同一个列表对象。

如果 `def` 语句本身被多次执行，则每次都会重新计算默认参数表达式，并创建新的函数对象。

例如：

```python
def create_fn():
    def fn(l=[]):
        l.append(1)
        return l

    return fn

a = create_fn()
b = create_fn()

print(a())
# [1]

print(b())
# [1]
```

这里 `a` 和 `b` 分别拥有自己的默认列表。

因此，默认参数为可变对象时，通常建议使用 `None`：

```python
def fn(l=None):
    if l is None:
        l = []

    l.append('a')
    print(l)
```

### 8.2 类属性

类定义代码块每次执行时都会创建对应的类对象，并在类命名空间中绑定类属性。

类属性中的可变对象可以被多个实例共同引用，因此通过一个实例修改该对象时，其他实例也能观察到变化。

这与函数默认参数的可变对象共享问题具有相似之处，但两者的对象保存位置不同：

- 函数默认参数保存在函数对象中。
- 类属性保存在类对象的命名空间中。

---

## 9. 核心理解

最后总结几个容易混淆的概念：

| 概念 | 解决的问题 |
| :--- | :--- |
| Scope（作用域） | 名称在哪里可以被访问？ |
| Namespace（命名空间） | 名称与对象之间的绑定关系保存在哪里？ |
| Binding（名称绑定） | 名称被绑定到了哪个对象？ |
| Closure（闭包） | 内层函数如何继续访问外围函数的变量？ |
| Lifetime（生命周期） | 对象何时创建、何时仍然存在、何时可以被回收？ |

最重要的规则：

1. Python 普通函数中的局部变量主要根据整个代码块中的名称绑定操作在编译阶段确定。
2. 普通名称查找遵循 LEGB：Local → Enclosing → Global → Builtins。
3. `global` 用于引用模块全局命名空间中的名称。
4. `nonlocal` 用于引用最近的外围函数作用域中已经存在的名称。
5. 修改对象与重新绑定名称是不同的操作。
6. 类作用域和推导式作用域存在特殊规则，不能完全按照普通函数作用域理解。
7. 作用域管理的是名称的可访问性，而不是对象本身的生命周期。
